## What the checks establish

coverage-validation.json records local JSON schema, source/ID references, per-concept question incidence, unused candidates, category counts and an acyclic proposed import graph. question-parser-results.json records actual Observable grammar results against every supplied expression, with hashes and invalid controls. A syntactically correct undeclared name and an invalid category expression intentionally pass: this demonstrates why grammar is not semantics. Semantic answerability, model availability and future consequence machinery are separate.

See [validation and preservation](VALIDATION.md) for exact check outcomes and the changed external checkout baseline. Existing two-file catchment overlay remains the only executable candidate and retains its newly explicit Earth Region ancestry blocker. No full domain candidate is ready for automatic code generation; no human approval has occurred.

## Review use

Review questions first, then source scope, ancestry and candidate bindings. Reviewers should challenge scientific importance, missing distinctions, overloaded meanings and causal scope, not merely prose or spelling. Source excerpts/introductions are not full specialist literature reviews; access failures and weak evidence remain visible. Fresh probes in REVIEW_FINDINGS.md were written by another agent with candidates visible, not a blind held-out expert.

The review freeze records exact source/import hashes in review-context.json and each dossier. Changes to imports invalidate affected scientific/semantic decisions. Backend review payload examples are illustrative and not submitted; server validation remains server-owned. Scientific acceptance, application and publication are distinct gates.
